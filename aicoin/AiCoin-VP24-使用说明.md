# AiCoin 成交量分布指标 VP-24 · 使用说明

基于成交量分布（Volume Profile）的日内均值回归指标。

- 价格区间均分 **24 档**，按重叠比例把成交量摊分到各档
- 中间 **70%** 成交量所在区间 = 价值区（VA），上沿 **VAH**、下沿 **VAL**
- 最密集档 = **POC**
- 收盘 > VAH → 高位低量区 → **做空区域**；收盘 < VAL → 低位低量区 → **做多区域**

## 文件说明

| 文件 | 用途 | 依赖 |
|---|---|---|
| `AiCoin-VP24-滚动窗口版.txt` | **推荐先用这个**。取最近 N 根 K 线计算 | 仅基础函数 |
| `AiCoin-VP24-每日08点重置版.txt` | 严格按「每日 08:00 起算」 | 额外需要 `hour()` 时间函数 |

**为什么给两个版本**：08:00 重置版依赖 `hour()` 时间函数与自引用 `x[1]`，而 AiCoin AIScript 的公开资料里没有确认这些函数。先用滚动窗口版跑通，确认平台支持 `highest/lowest/sum/max/min`，再上会话版，能避免一次面对一堆报错。

## 安装步骤

1. 打开 AiCoin PC 端 → 行情 K 线页面 → 拉到最底部 → **自定义指标**
2. 右上角 **新建**，把默认代码全选删除
3. 复制 `.txt` 文件里的全部内容粘进去
4. **保存**并命名，然后 **添加到图表**

## 参数调节

| 参数 | 默认 | 说明 |
|---|---|---|
| `N`（滚动版） | 24 | 回溯 K 线根数。**必须和周期匹配**：1小时→24（≈一整日）、30分钟→48、15分钟→96、4小时→6 |
| `VA_PCT` | 70 | 价值区包含的成交量百分比，标准值 70 |
| `MIN_BARS`（会话版） | 4 | 当日至少走完几根 K 线才认为有效，防止 08:00 刚重置时出假信号 |

## 两个版本怎么选

**滚动窗口版**（默认推荐）
- 每根 K 线都用「最近 N 根」的完整区间分档，边界和统计窗口同步，结果稳定
- 1 小时周期 + N=24 时，等价于「最近 24 小时」，与日频口径非常接近
- 不依赖任何时间函数，几乎肯定能跑

**每日 08:00 重置版**（严格符合你的要求）
- 真正的「每日从上海时间 08:00 开始计算」
- 但要注意：盘中的价格区间是**不断扩张**的，早上 09:00 的区间比晚上 20:00 窄得多，
  这会让早期 K 线的档位归属略有失真 —— **越接近次日 08:00 越准确**
- 如果 `hour()` 报错，按文件里注释的三种写法逐一试（北京时间 / UTC / 按自然日）

## 算法要点（为什么这么写）

**1. 成交量按重叠比例摊分，不能整根计入**
一根大阳线覆盖 5 个档，如果把它的全部成交量重复算进这 5 档，分布图会被抹平。
这里用 `ov / (high - low)` 计算每档应得的份额。

**2. 24 档全部展开为独立标量，没用循环和数组**
AiCoin 的 AIScript 是逐 K 线求值的向量语言，公开资料中未见 `for` 循环与数组支持。
所以 24 个档位写成 24 组变量，分位查找用「累加步进」代替嵌套三元：
```
VAL = lo + (c0 < T ? step : 0) + (c1 < T ? step : 0) + ...
```
从区间下沿出发，累积量不足 15% 就往上走一格，走到够为止。

**3. 强制把 POC 包进价值区**
分位数口径在分布极分散时可能把 POC（成交量最大档）甩在价值区外，
这违反「价值区必含 POC」的基本性质，所以做了一次夹逼修正。

**4. 一字线的成交量不会丢**
`high == low` 时重叠长度算出 0，若只按重叠判断这类 K 线的量会全部丢失，
已改为「价格是否落在该档」判断。

## 需要你确认的平台函数

生成的代码用了这些函数，若某个报错，按提示替换：

| 函数 | 备选写法 |
|---|---|
| `highest(high, N)` | `hhv(high, N)` |
| `lowest(low, N)` | `llv(low, N)` |
| `sum(x, N)` | 若不支持，可用 `cum` 差值或 `totalsum` 替代思路 |
| `max(a, b)` / `min(a, b)` | — |
| `cross_up(a, b)` / `cross_down(a, b)` | 若平台报错，改成 `crossup` / `crossdown`（去掉下划线） |
| `na` | 若平台无空值，把 `VAH_ = valid ? VAH : na` 直接改成 `VAH_ = VAH` |
| `hour`（仅会话版） | 见文件内注释三种写法 |

> **已修复「无绘图函数」报错**：当前版本使用最简 `plot(VAH_, title='VAH')` 等调用，
> 先保证能被 AiCoin 识别并渲染出三条线；样式参数（color/linewidth）在确认跑通后再加。

## 交易用法

指标画三条线：**VAH**、**VAL**、**POC**，并在价格上穿/下穿价值区边界时通过 `alertcondition`
触发预警。当前版本为了优先解决「无绘图函数」报错，暂时用最简 `plot` 画线，不带颜色和线宽；
若你需要彩色线条，可在 `plot(...)` 里补 `color='red'`、`linewidth=2` 等参数。

典型用法是**区间震荡市的均值回归**：

- 价格上穿 VAH → 进入高位低量区，市场不认可这个价格，倾向回落 → 做空
- 价格下穿 VAL → 进入低位低量区 → 做多
- 价格回到 VAH 与 VAL 之间 → 回归价值区，平仓

**它的前提假设是「价格会回归价值区」。** 在强趋势行情里这个假设不成立 ——
价格突破 VAH 后可能持续上行，此时做空会连续止损。建议叠加趋势过滤
（例如只在均线走平时启用反转信号），或把 VAH/VAL 当作突破确认位而非反转位来用。

## 已验证 / 局限

已用模拟数据验证：
- 生成的逻辑与「真正的分箱累积」参考实现**逐位一致**（误差 0.0000%）
- 会话版的 08:00 重置、当日累积、单调性均正确
- `lo ≤ VAL ≤ POC ≤ VAH ≤ hi` 恒成立
- 一字线、全平盘等边界不丢数据

需要知道的局限：

1. **价值区口径**：本实现按「上下各切 15%」的分位数法，与 TradingView / 快期等平台
   「从 POC 向两侧贪心扩展」的标准算法不完全等价。实测在真实感分布下两者相差
   **0~2 个档位**（多数场景 0~1 档），单峰分布下通常一致；在多峰、强趋势时差异会放大。
   分位数法无法在无循环语言中实现贪心扩展，这是取舍的结果。
2. **会话版盘中失真**：如前所述，边界随当日高低点扩张，早盘档位归属不精确。
3. **成交量来自 K 线，不是真实盘口逐笔**：本指标用的是 K 线的 `high/low/volume`，
   无法还原真实的逐笔成交分布，档位归属是线性摊分的近似。

> AiCoin 对 PRO 会员已内置「成交量分布 / 持仓分布」功能。若你只需要看图，
> 直接用内置即可；自定义指标的价值在于能加信号、箭头和预警。

## 风险提示

指标只描述「成交量在哪些价位集中」，不预测方向，也不构成投资建议。
VAH/VAL 是结构性参考位，不是必然的支撑阻力。
