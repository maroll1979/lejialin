## 开单逻辑（1h 定方向 + 15m 共振 + 5m 市场结构触发）

三个周期：**5m / 15m / 1h**（4h 已移除，30m 已改成 5m）。三层分工：

| 周期 | 角色 | 信号权重相关参数（look / ATR 上限 / ATR 系数 / 综合权重） |
| --- | --- | --- |
| 1h | **定大方向** | 30 根 / 2.4 / 1.80 / 44% |
| 15m | 共振确认 | 20 根 / 2.0 / 1.20 / 30% |
| 5m | **市场结构扳机**（不参与方向投票） | 16 根 / 1.6 / 0.90 / 26% |

触发条件：

1. 1h 必须有方向（多/空），观望则不开仓
2. 15m 必须与 1h 同向（共振）
3. 5m 出现**同向**的**市场结构触发**事件（见下节）

> **口径变更（v20260925a）**：旧版让 5m 也投票方向（「15m 与 5m 同时与 1h 同向 + 至少一个刚翻转」）。
> 新口径按用户给定的第 6 节规范，5m **不再判断大趋势**，只回答「现在能不能扣扳机」。
> 旧口径代码保留在 `findTriggers` / `findTriggersClosed`，回测传 `msMode:false` 即可切换做对照。

触发后在 K 线上画箭头标记（绿向上 = 买入，红向下 = 卖出），并弹提示（带 1h 方案止损/止盈）。

## 5m 市场结构触发（0–25 分）

5m 不判断大趋势，只负责扣扳机。结构定义**全部程序化**（固定 fractal 窗口找 pivot），不含主观画线。

| 触发模块 | 多头条件 | 分值 |
| --- | --- | --- |
| Swing Low 成立 | 已确认 pivot low 的新鲜度（≤10 / ≤22 / ≤40 根 → 3 / 2 / 1） | 0–3 |
| Higher Low | 新回踩低点高于上一个有效 Swing Low（幅度越大分越高） | 0–5 |
| Bullish CHOCH | 收盘突破最近一个有效 **Lower High** 超过 `0.10 × ATR` | 0–7 |
| Retest Hold | 回踩突破位未失守（未触及突破位 +1、收盘未破位 +1） | 0–4 |
| Bullish BOS | 回踩后收盘再破结构高点 | 0–6 |

空头侧完全对称（Swing High / Lower High / Bearish CHOCH / Retest Hold / Bearish BOS），
两个方向各算一套 0–25 分。

**触发条件（与规范里那行代码逐字一致）**：

```
long_trigger = setup_valid AND bullish_choch AND retest_hold AND bullish_bos
```

面板上可切到**宽松档**「核心条件满足 ≥ 2 个」——即「避免假信号」那段话给出的下限。
**绝不用单次 5m 金叉或单根阳线当反转。**

实现要点：

- **pivot 用固定 fractal 窗口**（左右各 2 根，共 5 根），中心根是窗口内极值才算数
- **结构位的有效性**：Lower High 只在「新 pivot high 低于上一个 pivot high」时刷新，
  Higher Low 同理；突破必须超过 `0.10 × ATR` 才有效，过滤噪音假突破
- **一次结构只响一次**：BOS 完成后把本次突破位记进 `lock`，
  要再次触发必须形成**新的** Lower High（`lastLH.p` 变化）
- **回踩窗口 12 根**、回踩容差 `0.80 / 0.35 × ATR`（到位 / 失守），超时未回踩视为作废
- 状态机：`0 等 CHOCH → 1 已 CHOCH 等回踩 → 2 已回踩等 BOS → 3 完成`（完成后下一根复位）

> ⚠ **无未来函数**：pivot 中心根要等它**右侧 2 根 K 线走完**才被确认
> （第 i 根喂入时才判定第 i−2 根），所以历史触发点在当时是真实可知的。
> 测试 13 用「改动后 30% 数据、前 70% 的事件与分值必须一字不差」来卡这条，
> 实测**事件泄漏 0 / 分值泄漏 0**。

> ⚠ **实盘与回测是同一份实现**：结构状态机只写在 `strategy.js` 的 `MsStream`，
> 看板调 `msReplay`（把最近 200 根 5m 冷启动重放），回测调 `msSeries`（全程连续流式）。
> 测试 14 卡两者一致率，实测**方向一致率 100%、结构分最大偏差 0.00**。

### 八因子信号引擎（状态量口径）

单个周期的方向分由 **8 个因子加权**而成，每个因子映射到 `[-1, 1]`（正 = 多、负 = 空）：

| 因子 | 权重 | 关注的状态量 | 明确不看 |
| --- | --- | --- | --- |
| `trend` EMA | 0.15 | 快慢线斜率、两线距离及其变化、价格与 EMA 的偏离 | 单次金叉 / 死叉 |
| `macd` | 0.14 | Histogram 值、**一阶变化**、**二阶加速度**、背离 | 是否 > 0 |
| `adx` | 0.13 | 绝对强度连续映射、连续上升/下降速度 | 单个阈值（如「> 25 才算趋势」） |
| `rsi` | 0.11 | 所处区域、斜率、背离、**脱离极端区** | 超买超卖本身 |
| `kdj` | 0.10 | **钝化持续时间**、脱离极端区 | 金叉 / 死叉 |
| `boll` | 0.10 | Band Width 分位、**z-score**、假突破后回归 | 触碰上下轨 |
| `obv` | 0.13 | 是否**确认**价格新高/新低（确认/背离） | 绝对数值 |
| `vol` | 0.14 | **RVOL**、climax、结构位放量 | 简单放量 |

权重和为 1.00。几个实现要点：

- **量纲统一**：所有价格差一律除以 **Wilder ATR(14)**，变成「几个 ATR」，
  因此 5m/15m/1h 三个周期、BTC/ETH/黄金不同品种共用同一套阈值。
- **ADX 连续映射**：`adxStr = clamp((adx − 12) / 28, 0, 1)`，再乘速度项
  `(adx − adx₆) / 6` → 强度是渐变的，不存在「过线才算数」的跳变。
- **二阶加速度**：`h2 = (hist − 2·hist₁ + hist₂) / ATR`，抓的是柱状图「加速放大/收敛」
  而不是它的正负。
- **KDJ 钝化状态机**：D > 75 或 < 25 进极端区；连续 ≥ 5 根仍在区内 → 给**顺势分**
  （钝化越久趋势越真）；脱离极端区且上一段 ≥ 3 根 → 给**反向分**。完全不含金叉死叉。
- **OBV / Volume 都不看绝对量**：OBV 只在「价创新高且 OBV 同步新高」时给 +1，
  价新高但 OBV 不确认给 −0.8（顶背离），无新高新低时退化为弱参考（限幅 ±0.35）。
  Volume 用 RVOL = 当前量 / 前 120 根均量，只有在**结构位**（前 20 根高低）放量
  或 RVOL ≥ 3 的 climax 才给分，单纯放量不给方向。

**两道闸门**才允许出方向：① 加权分绝对值 ≥ 0.20；② 价格与 EMA 偏离
`|devA| ≥ 0.30 ATR`（趋势锁定，避免在均线缠绕处反复打脸）。

**实盘与回测的口径差异（重要）**：实盘用的是**进行中**的那根 15m/1h K 线（时效优先）；
回测必须只用**已收线**的 K 线，否则等于偷看未来。见下节。

## 5 年回测

面板：进度条 + 11 张结果卡 + 最近 24 笔明细 + **结构总分分档表** + 口径说明。BTC 一次约 80 秒
（526 段并发拉 5m K 线，共约 52.6 万根）。

**无未来函数的三处保证**（否则回测结论必然偏乐观）：

1. 1h / 15m 只取**已收线**的 K 线 —— `buildMap` 给的是「包含当前 5m 的那根」
   （91.7% 的抽样点都还没走完），回测改用 `buildClosedMap`
2. 入场价取**触发后的下一根 5m 开盘价**，不是触发那根的收盘价
3. 止损止盈用的是 **截至当时** 的 1h K 线（`tailObjects(s1h, 已收线索引, 300)`）

同一根 K 线内同时触及止盈与止损时**保守按止损计**；扣 0.10% 市价手续费（开平各一次）；
最多持仓 2016 根 5m（7 天）超时按市价平；权益曲线按「每笔风险 = 当前权益 2%」滚动。

旧口径（`msMode:false`）里，已收线的 15m/1h 在一整组内不变，照搬实盘的「上一根比较」
会在组内每根 5m 重复触发，故改用「共振状态由 **未共振 → 共振** 的跃变沿」，一次共振只开一次仓。

新口径（默认）不需要这一步：**市场结构触发本身就是离散事件**（BOS 那一根只响一次，
且同一结构位被 `lock` 锁住），一次结构只会开一次仓。
`backtestCore` 支持 `opt.cache` 复用「聚合 + 三周期方向序列 + 结构序列」，
所以 `cmp-ms.js` 能在同一份 K 线上跑 8 种配置做对比（第一次约 7s，之后每次 <1s）。

**信号口径一致性**：`strategy.js` 的流式引擎与 `app.js` 的 `computeSignal` 严格同式，
600 根逐根对照：**方向一致率 100%、综合分数偏差 0.0000、逐因子最大偏差 0.0000（最差 adx）、
符号翻转 0 处**。测试会逐个因子断言（`trend/macd/adx/rsi/kdj/boll/obv/vol`），
任一因子偏差 ≥ 0.02 或出现符号翻转即失败。

流式侧为了做到 O(1)：Wilder 序列（ATR / DI± / ADX）用累加器递推，
OBV 与高低点窗口用定长环缓冲 `Ring(n)`，KDJ 钝化用增量状态机 ——
其中 OBV 语义是「取最近 200 根重算整条 ov 序列」，用全局前缀和 + EMA 加权和递推复现。

| 严格 · 结构分 ≥22 | 85 | 35.3% | −6R | +0.0548 | 0.45 | 0.127 |
| 宽松（核心 ≥2） | 722 | 33.5% | −78R | +0.0079 | 0.19 | 0.116 |
| 宽松 · 结构分 ≥16 | 186 | 37.1% | −6R | +0.0869 | 1.04 | 0.119 |
| 严格 + 5m 方向也同向 | 297 | 36.7% | −14R | +0.0747 | 1.13 | 0.123 |

#### 结论（四条，不粉饰）

1. **结构触发做到了它该做的事：砍频率。** BTC 3712 → **448 笔**、ETH 3886 → **435 笔**
   （约 0.25 笔/天），把 97% 的 5m 结构事件挡在 1h·15m 滤网之外。这正对应
   「5m 只负责扣扳机、避免假信号」的定位。
2. **但它没有创造新的 alpha。** 严格档单笔毛利 BTC +0.0355（t=0.66）、ETH +0.0705（t=1.29），
   **两个都不显著**；两品种均值 ≈ +0.053，与旧口径的 +0.054 几乎一样。
   换句话说：这层做的是**过滤与降频**，不是提高期望。
3. **「最低结构分」不是有效过滤器 —— 分数越高反而越差。** BTC 上
   13–15 段 +0.160R/笔（n=41）→ 19–21 段 −0.019（n=200）→ 22–25 段 −0.014（n=77）；
   ETH 上没有单调关系（19–21 段反而 +0.098）。所以面板里**默认「不限」**，
   把结构分当参考而不是门槛。合理解释：分数高意味着 CHOCH/BOS 的突破幅度大，
   等确认时价格已经走完一段，入场价更差。
4. **净期望仍为负，因为手续费依然是毛利的 2～4.6 倍。** 止损宽度 1.5%（BTC）/
   2.0%（ETH）时，一来回 0.2% 的手续费就是 0.16R / 0.12R / 笔。严格档把笔数压到 1/8，
   ETH 的累计亏损从 −262R 缩到 **−21R**、BTC 从 −423R 缩到 −57R ——
   **亏得少了，但没转正**。盈亏平衡需要毛利 ≥ 0.118R/笔（ETH）/
   0.16R/笔（BTC），而实测只有 0.07 / 0.036。

严格档与宽松档哪个更好**没有可信结论**：BTC 上宽松略好（净 −0.091 vs −0.126），
ETH 上严格明显好（−0.048 vs −0.108），方向相反。默认按规范里的**严格档**。

**这是历史统计，不代表未来收益。** 滑点、资金费率与深度不足造成的成交偏差均未计入。
真正的改善方向仍然在成本结构（降频 / 放宽止损 / 换 maker 费率），不是继续加条件。

## 九指标投票制（现行开单逻辑 · 2026-09-28 起）

> 起因是用户的一句：「9 个指标**同时**共振，发生机会太小了」。
> 于是把方向判定从「加权求和」换成**多数票表决** —— 每个周期把九个指标各自离散成
> 「多 / 平 / 空」三态票数，按票数定方向，而不是要求九个全部同向。

### 九个指标与投票口径

| # | 指标 | 投「多」 | 投「空」 | 投「平」（未表态） |
| --- | --- | --- | --- | --- |
| ① | EMA 趋势 | 因子值 ≥ +0.30 | ≤ −0.30 | \|v\| < 0.30 |
| ② | MACD 动能 | 同① | 同① | 同① |
| ③ | ADX 趋向 | 同① | 同① | 同① |
| ④ | RSI 摆动 | 同① | 同① | 同① |
| ⑤ | KDJ 摆动 | 同① | 同① | 同① |
| ⑥ | BOLL 通道 | 同① | 同① | 同① |
| ⑦ | OBV 量价 | 同① | 同① | 同① |
| ⑧ | VOL 量能 | 同① | 同① | 同① |
| ⑨ | **MA200 位置** | 收盘价高于日线 MA200 且偏离 > 0.5% | 低于且偏离 > 0.5% | 落在 ±0.5% 死区内 |

①–⑧ 直接复用 `SignalStream` 已有的八因子输出（`f.trend` … `f.vol`），⑨ 就是 K 线上那条紫色虚线。
每个指标的阈值统一为 `0.30`（可调），第九票另有 `0.5%` 死区 —— 价格贴着均线反复穿越时，
它会不停在「多/空」之间抖出噪音票，留个缓冲才只在明确站上或跌破时表态。

### 票数 → 方向

赢家票数 ≥ `minVotes` **且严格多于**反对方：

| 票型 | 判定 | 说明 |
| --- | --- | --- |
| 2 多 · 3 平 · 4 空 | **看空** | 用户的原始口径，4/9 ≈ 44% 同频确认 |
| 4 多 · 4 空 · 1 平 | 观望 | 打平，谁都没胜出 |
| 1 多 · 8 平 · 0 空 | 观望 | 只有 1 票支持，不算方向 |

第三条是最容易写错的地方：**若用「净票数符号」判定，1 多 8 平会被判成看多**，
等于让一个孤独的指标决定方向。写成「必须达到 minVotes 且严格多于反方」才是对的，
`tests/test-strategy.js` 里有专门的断言盯着这个反例。

### 触发：1H 定方向 + 15m·5m 同向

三个周期的**方向都由票数决定**，然后 1H 定方向，15m 与 5m 同时与之同向，
在两个小周期**刚凑齐的那一根**触发一次 —— 状态持续不重复报警，一次共振只响一次。

### 为什么要换掉加权求和

加权制里，一个因子给 ±1、其余八个全是 0，总分照样能被推过阈值 ——
表面是「九项综合评分」，实际是「一个指标说了算」。
投票制把「有几个指标在说话」显式写成 `minVotes`，调松紧只有一个旋钮，结论也能逐条复核。

### 三条实测结论

**① 改成多数票之后，方向预测力第一次在统计上站住了。**

**② 但净期望仍然是负的，卡点在手续费，不在信号。**
每笔毛利 +0.063R，每笔手续费 **0.179R**，费用是毛利的 **2.8 倍**。

### 两个必须诚实说的点

- **第九票 MA200 的贡献没有通过样本外检验。**
  加上它之后，BTC 每笔毛利从 +0.042R 升到 +0.063R，但 ETH 从 +0.083R **降**到 +0.069R。
  两品种不同号 → 第九个指标带来的增益**无法证实**。真正起作用的是
  「加权求和 → 多数票」这个结构变化本身，不是多加了哪个指标。
- **≥6 票看起来最好，但不能推荐。** 它的单位质量确实最高（BTC +0.098R / ETH +0.134R），
  然而净期望 BTC −0.080R、ETH +0.007R —— **不同号**，且样本只剩 437 / 424 笔。
  ETH 那个 +0.007R 的 t 值只有 0.13，纯属噪声。

### 实现上的三处防坑

1. **MA200 一律取「已收盘日线」。** 当日还没走完的日线里装着今天的收盘价，
   直接拿它跟盘中比就是偷看未来。纯函数 `dailyMa200Lookup` 用 `buildClosedMap` 对齐，
   `tests` 里有一条专门的断言：构造一批落在某个交易日开盘半小时内的 5m bar，
   验证取到的 MA200 恰好等于用**前一天**为止的 200 根日线算出的值
   （实算得到 1199.5000，若错用当天会是 1200.5000，差值被断言挡住）。
2. **回测统一剔除 MA200 预热段。** 前 200 天第九票恒为「平」，
   若让新体系从这段开始、旧体系从头开始，等于换掉了对比的起跑线。
   两边都从同一根 5m 开始，差异才只来自「方向怎么判」。
3. **页面与回测共用同一套 closed 口径。** 面板刻意调用同一个 `findVoteTriggersClosed`，
   所以图上看到的信号能被 `vote-bt.js` 逐根复现，不会出现「图上赚钱、回测亏钱」。

> ⚠ **这套逻辑目前不具备盈利能力。** 在双边 0.1% 的市价单费率下，
> 五年双品种净期望都是负的。它能证明的事情只有一件：
> **方向判断这部分终于做出统计显著的正毛利了**，剩下的差距全部在摩擦成本一侧。

### 三个实现上的关键决定

- **背离必须是 pivot 口径 + 带有效期。** 最初写成「收盘价创 30 根新低而 RSI 不确认」，
  结果 15m Setup ≥18 的命中率极低 —— 因为背离只在确认那一根存在，几乎不可能与 5m 扳机撞上。
  改为「比较两个已确认 pivot low 的价格与指标值」，
  并让背离在 **16 根内满分、40 根后线性失效**，跨层才真正能遇上。
- **Confirmed / Live 双状态并存，且不能为了第二套再跑一遍 32 万根 `VStream`。**
  回测一律走 Confirmed（`buildClosedMap`，已收线）—— 这是「无未来函数」的三处保证之一。
  实盘面板同时给出两套：`decideNow` 返回 `{ confirmed, live }`，
  Live 过了 Gate 而 Confirmed 没过时，面板标「仅预警」而不是信号。
  两套口径**共用同一份 `tfScores`**（评分与 live 与否无关），只有索引映射不同，
  否则单次刷新要从 6.7s 变成 4.3s 的双倍开销。
- **实盘面板各周期单独取数。** `build(opt.tfs)` 允许传入真实的 15m/30m/1h/4h 序列。
  否则从 5m 聚合最多只有 7 天（Gate 单次 2000 根），4H 只有 41 根、ADX 还没热身完。

#### v2.1 的五条结论（不粉饰）

1. **规范门槛 70/75/85 严格到统计上不可用**：BTC 5 年 18 笔、ETH 13 笔。
   这套 100 分制真正的用途是**风险分层与描述**，不是当过滤阈值硬用。
2. **顺 4H 是唯一有统计支撑的分组，但只在 BTC 上成立。**
   BTC 顺 4H 毛利 +0.144R（t=2.71，显著），ETH 上是 0.000R —— 完全消失。
3. **「顺 4H + 止损放宽 1.5 倍」能让 BTC 净转正到 +0.038R，但 t=0.69 完全不显著，
   而且是先在 BTC 样本内挑出来的倍率。** 样本外（ETH）同一参数是 **−0.147R（t=−2.70，显著为负）**。
   **不要据此入场** —— 这是典型的单样本过拟合，一致性检验直接判了它死刑。
4. **30m 层的价值是「排除」不是「加分」**：衰竭组本身没有更高期望，
   但用它去拦「追在强趋势末端」的那 61% 信号，是唯一站得住的用法。
5. **净期望仍为负**：手续费 0.12～0.17R/笔，是毛利的 2～5 倍。
   继续加条件（完整三段、更高门槛、更高结构分）都不会让它转正；
   真正能改的只有**成本结构**（放宽止损 / maker 费率 / 降频），而放宽止损的代价是持仓时间与回撤同步放大
   （BTC 平均持仓 23.4h → 42.9h，最大回撤基本不变）。

## 200 日均线（日线 SMA200）

K 线图上的**紫色虚线**，口径固定为**日线**：一律用日线收盘价算 200 日简单移动平均，
与当前显示 5m / 15m / 1h 无关。三个周期看到的是**同一条日线级别长均线**
——否则在 5m 图上按 200 根 5 分钟来算，「日线级别牛熊分界」的语义就不成立了。

**实现要点**（`strategy.js` 的三个纯函数 + `app.js` 的渲染层）

| 函数 | 职责 |
| --- | --- |
| `smaCalc(vals, p)` | 滑动窗口简单移动平均；前 `p−1` 根返回 `null`（窗口不足不产出） |
| `ma200FromDaily(daily, p)` | 日线 → SMA200 散点，返回 `{points, last, prevDay, n}`；日线不足 `p` 根时**诚实返回空**，页面会显示「取不到 XXX 的原因」而不是留一条空线 |
| `maWindowProject(points, candles, padSec)` | 把日线散点裁剪/投影到当前 K 线时间窗 |

两个必须注意的坑，都写进了测试：

1. **不裁剪会毁掉整张图。** 若把几百天日线原样喂给图表，
   `timeScale().fitContent()` 会把可视范围拉到几百天，5 分钟图瞬间被压成一根竖线。
   所以必须先与 K 线时间窗求交集（首尾各留 1 天余量保证连线不断）。
2. **窗口太窄会画不出线。** 5m 图只跨约 1 天，窗口内日线点可能不足 2 个，
   而**单点 line series 是不显示的**（什么都不出现）。
   因此不足 2 点时退化为「逐根 K 线前向填充」，保证任何周期都看得见这条线。

**数据源**：Gate.io 永续日线 K 线，取 400 根（200 根冗余，保证能算出 200 个以上的均线点）。
日频数据变化慢，缓存 30 分钟，不跟着 5 分钟一次的行情刷新重复调接口。
美债品种没有 K 线，自动隐藏该线与图例。

**图例**（图表左上角）三项读数：MA200 数值 · 现价偏离百分比（上方红 / 下方绿）·
均线自身方向（上行 / 下行 / 走平，按日环比判断）。
「价格在上方多少」与「均线自己往哪走」是两件事，分开看比只看一侧信息量大。

行情页面最忌讳的是**数据悄悄不动了、界面却看起来一切正常**。

**页面版**：切到该页自动跑（也可手动点按钮 / 勾选每 5 分钟自动跑）。

| 检查项 | 归属 | 判定口径 |
| --- | --- | --- |

**当前实测（本终端网络环境，2026-09-28）**

主源 **9/9 全部可用**（延迟普遍 40–500ms，WebSocket 收到推送在秒级）。
辅助源 4 项降级，均为外部原因且已有替代路径：

1. **财政部 fiscaldata JSON 接口已下架** —— 三个候选端点全部返回 404。
   主源早已改为官网 CSV 直连（`CORS: *`，当日/跨年拼接，实测最新数据 09/25/2026），功能不受影响。
2. **OKX / Coinbase / Bitstamp 域名在本网络不可达** —— 6 秒超时。
   属本机 DNS 污染，非程序故障；比价栏留空，主流程照常。

### 实测顺带查出并已修复的问题

- **逐笔成交时间戳口径错**：Gate 的 `create_time_ms` 与 `create_time` **同为秒**（值相等，只是小数精度不同）。
  原代码 `Math.round(+t.create_time_ms)` 会把它当毫秒读，得到 1970 年的成交时间。
  该函数（`aggTrades`）当前无人调用，故线上未实际受影响，但隐患已消除，并写死一行注释说明原因。
- **`liq_orders` 窗口限制**：接口要求 `from`/`to` 区间**不得超过 1 小时**，否则 `INVALID_PARAM_VALUE`。
  初次写探针时用 24 小时窗口，误报成「接口不可用」；实际 `liq-map.js` 已按 `to − 3599` 正确切片。
  这类「接口侧硬性限制」很容易在写验证脚本时被误判，已记入下方防范点。

写自检脚本时的三条经验：
① **判定口径必须与页面实现完全一致**（比如美债 CSV 的 `MM/DD/YYYY` 要走 `normDate`，直接 `new Date()` 会 Invalid Date 而误判失效）；
② 区分**主源失败**与**辅助源降级**，不要把后者混进来制造假警报；
③ 结果要**能被人眼复核**，所以每项都带上原始读数（条数、最新时间、盘口价差）而不是只给一个勾。

## 胜率为什么只有 36%（归因）

口径：页面默认的严格档（CHOCH+回踩+BOS），BTC 448 笔 / ETH 435 笔，`node diag-winrate.js <品种>` 可复跑。

**1. 胜率是被退出结构锁死的，不是入场质量差。**
`TP1=1R 减半 / TP2=2R / 止损 1.8×ATR` 这套规则下，「赢」等价于**至少走到 2R**：
走到 TP1 后回落止损的毛利恰好为 0（0.5×1R − 0.5×1R），扣手续费后是 −0.16R，算亏。
所以净胜率在数学上 ≈ P(走到 2R)。完全随机入场在这套规则下就是 **33%**，策略 **36%**，只高 3 个点。
把出场规则换成「不减仓等 2R」或「TP1=0.5R 减半」，**胜率一模一样是 35.9%**，只有期望不同 —— 胜率由退出结构决定，与信号质量基本无关。

**2. 亏损几乎全部来自手续费（主因，且是唯一确定的一条）。**
BTC：毛利 **+15.2R**，手续费 **−72.6R**，净 **−57.4R**。止损平均只占价格 **1.53%**，
双边 0.1% Taker 折合 **0.162R/笔**（吃掉风险本金的 16%）。费率降到双边 0.02%（Maker + VIP）时净期望刚好归零（+0.002R，t=0.03）。

**3. 信号 alpha 微弱，统计上不成立。**
相对「同时刻 · 随机方向」的优势：BTC +0.053R / ETH +0.094R，两品种同号，倾向认为有微弱方向预测力；
但毛利 t 值只有 0.63（BTC）与 1.29（ETH），**都远没到 2**，样本不足以证明有 edge。

**4. 放宽止损是两难，不是解药。**
risk 从 1.8ATR 放到 5ATR：费 R 0.162 → 0.032、胜率 36% → 44%，但毛利同步稀释 +0.034 → +0.004
（说明预测力集中在入场后很近的距离）。两条曲线相抵，净期望仍为负，只是趋近 0。

**5. 别拿「近年变差」当结论。**
BTC 按年净 R：2021 +0.26 / 2022 +0.14 / 2023 +0.03 / 2024 −0.19 / 2025 −0.29 / 2026 −0.33，
三连负看起来像 alpha 衰减。但 ETH 同期正负交替（−0.08 / −0.10 / +0.05 / −0.11 / +0.02），**没有同样形态**
→ BTC 的三连负更可能是噪声，不构成可靠规律，也不该当作改进的出发点。

## 1m 回测 与 手动百分比止盈止损（2026-09-28）

回测不再绑死在 5m 上，出场也不再走 ATR —— 止损 / 止盈改成**用户手填的成交价百分比**。
回测面板上可以分别指定：撮合粒度（1m / 5m）、信号最低周期（1m / 5m）、年限、止损 %、止盈 %，
并实时算出**扣掉手续费后的保本胜率**。

### 为什么「50% 胜率配 1:1」在真实费率下不够

用户常见的判断是「我胜率 50%，那 1:1 就能赚」。这在**零手续费**下成立，现实里差得远。

设 S = 止损%、T = 止盈%、f = 单边费率，所有量除以成交价：

```
净赢一笔 = T − f(2+T)          净输一笔 = −(S + f(2−S))
p·净赢 + (1−p)·净输 = 0   →   保本胜率 p = (S + f(2−S)) / ((T+S)(1−f))
```

`Strategy.breakevenWinRate(stopPct, tpPct, feeSide)` 就是这个公式，页面实时调用它。

| 出场方案 | 零费率保本 | Taker 单边 0.1%（进出 0.2%） | Maker 单边 0.01%（进出 0.02%） |
| --- | --- | --- | --- |
| 1:1　1%:1% | 50.0% | **60.0%** | 51.0% |
| 1:2　1.5%:3% | 33.3% | **37.8%** | 33.8% |
| 1:2　1%:2% | 33.3% | **40.0%** | 34.0% |
| 1:3　1.5%:4.5% | 25.0% | **28.3%** | 25.5% |

**止损越窄，手续费占比越高**：1% 止损下进出一次就是 0.200R（20% 的风险本金），
1.5% 止损下是 0.133R，2% 止损下只有 0.100R。这就是为什么同为 1:2，`1.5%:3%` 的保本线（37.8%）
明显低于 `1%:2%`（40.0%）。

### 三个变量必须分开：`bt-pct.js` 的 A/B/C 三档

| 档 | 撮合粒度 | 信号最低周期 | 隔离出的变量 |
| --- | --- | --- | --- |
| A | 5m | 5m | 基准 |
| B | **1m** | 5m | 只提高成交分辨率 |
| C | 1m | **1m** | 只降低信号周期到 1m |

B 档的落地依赖 `mapLastBase()`：把「第 i 根 5m 收线」精确映射到它内部的最后一根 1m
（= t₅ₘ + 240s），再从它的下一根开盘成交。**这条由单元测试逐笔断言 A 与 B 完全一致**。

**实测（BTC / ETH 各 2 年，数据同源）**：

1. **撮合精度几乎没有价值。** A→B 的每笔净 R 差值在 7/8 组方案上是 `+0.0000`，
   只有最窄的 1%:1% 档出现千分之一级的差别（ETH +0.0012R）。
   原因是这些止损宽度下，一根 5m 内根本不会同时触及两端 —— 路径歧义压根没发生。
   **止损窄到 0.3% 以下，1m 撮合才真正开始有意义**（实测此时差 +0.0115R）。
2. **真正改变结果的是信号周期。** B→C 让笔数从约 1750 涨到约 3900（×2.2）。
   方向上有一点改善但**依赖出场方案**：`1.5%:3%`（BTC +0.013 / ETH +0.033）与
   `1.5%:4.5%`（BTC +0.032 / ETH +0.032）两品种都改善；`1%:1%` 与 `1%:2%` 则不同号。
3. **同盈亏比之下，宽止损一律优于窄止损**（BTC 8/8、ETH 8/8，共 16/16 组同向）。
   这是本轮唯一完全稳健的结论，本质是手续费占比被摊薄。

### 可行门槛：`bt-fee.js`

同一批入场点只改费率，找到「两个品种同时转正」的最高单边费率：

| 出场方案 | 可行单边费率 | 折让幅度 | 结论 |
| --- | --- | --- | --- |
| 1:1　1%:1% | 0（扫到零费率仍不成立） | — | **完全不可行**，放弃 |
| 1:1　2%:2% | 0.020% | 现费率 20% | 需深度 VIP + Maker |
| 1:2　1%:2% | 0.020% | 现费率 20% | 同上 |
| 1:2　1.5%:3% | 0.040% | 现费率 40% | Maker 档即可 |
| **1:2　2%:4%** | **0.080%** | **现费率 80%** | **最实用**：双边 0.16% 就转正 |
| 1:3　1%:3% | 0.020% | 现费率 20% | 需深度 VIP |
| **1:3　1.5%:4.5%** | **0.080%** | **现费率 80%** | **期望最高**，Maker+VIP 下两品种显著为正 |

Maker+VIP（单边 0.01%）下的表现：

- `1:3　1.5%:4.5%`：BTC **+0.104R（t=3.84）** / ETH **+0.096R（t=3.28）**　← 两品种同号且显著
- `1:2　2%:4%`：BTC **+0.073R（t=3.35）** / ETH **+0.075R（t=3.17）**　← 两品种同号且显著
- `1:2　1.5%:3%`：BTC +0.055R（t=2.50） / ETH +0.046R（t=1.95）

### 实现要点

- `strategy.js` 新增 `TF_SEC['1m']`；`backtestCore` 的 `baseSec` / `sigSec` / `maxHold` /
  持仓时长换算全部参数化，旧的硬编码 `TF_SEC['5m']` 与 `×5/60` 已清除。
- 出场：`stopPct` / `tpPct` 以成交价为基准；`tpMode='single'`（到 tp 全平，即用户描述的 1:1 / 1:2）
  或 `'split'`（tp1 减半 + 余仓推到 tp2Pct，默认 2×tp）。两者互斥于旧的 ATR 方案。
- `mapLastBase(sigT, sigSec, baseT, baseSec)` 负责粗周期索引 → 该周期内最后一根细 K 线。
- `cache` 必须带 `sigSec` 与 `votesKey`：`ma5`/`r5` 属于信号序列域，信号周期不同就不可复用。
- 浏览器里 1m 长周期会内存吃紧，页面给出预计根数与超过 120 万根的警示。

## 多空清算图

## 多空热力图（订单簿口径）

数据 = 永续订单簿在**现价上下 N 个 tick** 内的挂单分布。面板按价位分档画**背靠背柱**：
**价格下方的买盘挂单向左（绿，多头阵营）**、**价格上方的卖盘挂单向右（红，空头阵营）**，
中间竖线是多空分界，蓝线是现价，左右是价格刻度（右侧标出相对现价百分比）。
可**滚轮上下缩放**（以光标所在价位为锚）、**按住拖动平移**、**双击复位**。

**视野**：`±200` / `±500`（默认）/ `±2000` / `±5000` tick。tick 取合约的 `order_price_round`
（BTC 0.1、ETH 与 XAU 0.01、BNB 0.05、PAXG 0.1），所以 ±500 tick 对应的实际幅度随品种变化很大
（BTC 约 ±50 USDT / 0.06%，BNB 约 ±25 USDT / 3.26%）。

**柱长** = 该价位区间内的挂单名义金额 = `张数 × quanto_multiplier × 价位`（USDT）。

> ⚠ **挂单 ≠ 未平仓合约（OI）**。订单簿上的挂单是尚未成交的委托，随时可撤改；
> OI 是已成交未平仓的持仓。右侧卡片里 OI 单独一行并标注来源，不与挂单量混排。

### 订单簿接口的两个硬限制（改这块前必须知道）

1. **单侧最多 300 档**：`limit` > 300 直接报 `TOO_BIG: limit 300`
2. **`interval`（价格分组粒度）只接受离散值** `{0} ∪ {1,5}×10^k`
   —— `interval=2`、`20` 会返回 `INVALID_PARAM_VALUE: Invalid request parameter interval value`

实测覆盖（BTC，tick=0.1）：

| interval | 覆盖范围 | 粒度 |
| --- | --- | --- |
| `0`（原始价位） | ±1600~2100 tick | 每个 tick 可见 |
| `1` | ±3600 tick | 10 tick/格 |
| `5` | ±15000 tick | 50 tick/格 |

所以代码里做了**粒度自适应**：按当前视野估算需要的 tick 数 → 选最小够用的 interval →
取回来发现覆盖不够就换更粗的重取（最多 4 次）。滚轮缩小到超出覆盖范围会自动取更深的簿，
放大回来则换回更细粒度。分档用的是同一份订单簿重新分桶，**不重新联网**。

标注线：最厚买盘墙、最厚卖盘墙、24h 高低（落在视野内才画）、现价；标签按 y 排序自动下推防重叠。
右侧 10 张卡片：盘口方向（按挂单失衡）、买/卖盘挂单量与占比、买卖挂单比、最厚买盘墙/卖盘墙、
**真实未平仓合约（来自 tickers，标注「非挂单」）**、资金费率、现价/标记价、买一/卖一与价差。

真实发生的爆仓走势仍保留在 **K 线左侧的多空清算图**（`liq-map.js`，按 24h/3天/7天 统计真实强平单）。

### 量能结构带（2026-09-28 新增）

把订单簿读成一张**流动性地图**，回答「哪里堆着墙、哪里是空的」。面板上的「量能带」按钮可开关（默认开，偏好记在 `simtrader_lsbands_v1`）。四个层次：

| 结构 | 算法 | 交易含义 |
| --- | --- | --- |
| **POC**（挂单最密集价位） | 单位价位内挂单金额最大的那一格 | 全图最拥挤的价格，多空争夺的核心 |
| **中间聚集带（价值区 VA）** | 从 POC 向两侧贪心扩张到累计 **70%** 挂单额为止 | 在保证占比的前提下**最窄**的价格区间 = 市场公认的价值中枢 |
| **上方最薄带** | 只在**卖盘侧**滑窗找总额最小的一段（窗口 = 视野的 12%） | 往上突破时阻力最小的路径 |
| **下方最薄带** | 只在**买盘侧**找 | 往下砸时阻力最小的路径 |

VA 的贪心扩张是 Market Profile 的标准做法 —— 每一步都纳入左右两侧中更大的那个，因此**同等占比下区间最窄**这个最优性是算法保证的，不是调参调出来的。

渲染分三层：**左侧一根 22px 的「价位轴」**（只标位置、不标长度，不会被柱状图挤压）+ **横贯绘图区的淡色底带** + **贴在绘图区左缘的结构标签**（右侧留给 24h 高低与最厚墙，两边不打架）。

#### 三个必须记住的坑（都是真实数据打出来的）

**① 空洞必须分侧找。** 买盘只存在于买一以下、卖盘只存在于卖一以上，两侧在价格上**互斥**。
所以 `tot[i] = bid[i] + ask[i]` 求总额是对的（每格仍等于该价位的挂单总额、不重复计数），
但用它找「稀薄」会越过买卖分界、被另一侧的 0 拉低，选出横跨两侧的假空洞。
第一版就犯了这个错，算出来的「上方空洞」整个落在价值区内部。

**② 稀疏度的基线要用中位数，不能用均值。** 稀疏度 = `该段均值 ÷ 同侧挂单的中位数`。
订单簿的常态是「少量巨墙 + 大量普通单」；用均值时那堵巨墙会把基线抬高 ——
实测 35 格 `$1000` + 1 格 `$50000` → 均值 `2361`，结果**均匀的普通挂单反过来显得稀薄**
（稀疏度被压到 `0.42` 而误判成真空）。改中位数后同一份数据就是 `1.00`，符合直觉。
`test-band.js` 里有一条专门的回归断言盯着这个数。

**③ 视野越窄越不可信。** 小视野把盘口切碎，每格里要么是孤立大单要么几乎为零
（ETH ±400 tick 时同一视野内 `$54` 与 `$708K` 并存），「最小量能带」退化成在噪声里挑冠军。
所以做了两条诚实性兜底：**VA 宽度 > 75% 视野** → 标签写「无明显聚集带（价值区宽达 N% 视野）」；
**稀疏度 ≥ 0.5** → 标签写「上方薄弱（不显著）」，而不是硬指一个洞。
实测 BTC 在 ±5000 tick 下常出现上下都不达阈值，那时结论就是**没有明显空洞**。

#### 滑窗的固有语义

窗口宽度固定为视野的 12%，算法回答的是「**这么宽**的一段里哪段最薄」，
不是「任意宽度的空洞在哪」。标签里会写出 `宽 N tick`，请勿脱离这个尺度解读。
（第一版测试里把 `sum` 断言成 0 却拿到 `5014`，就是因为构造的真空只有 4 格而窗口有 9 格 ——
这是滑窗法的正常行为，不是 bug。）

#### ETH 实测读数（2026-09-28 23:5x，±5000 tick = ±1.86%）

```
视野内  买 $77.1M / 卖 $90.3M
POC     2,673.61   $9.65M       ← 在现价下方 0.59%
VA      2,665.97 – 2,711.80     占 70.4% 量能，宽度 46% 视野
上方最薄带 2,720.14 – 2,732.64   $5.98M  稀疏 0.270  （+1.14% ~ +1.60%）
下方最薄带 2,653.47 – 2,665.97   $1.95M  稀疏 0.157  （-1.34% ~ -0.88%）
```

下方空洞只有 `$1.95M` 而上方有 `$5.98M`、稀疏度 `0.157` vs `0.270`
→ **下方更接近真空，往下走阻力更小**。VA 中心 `2,688.9` 与现价 `2,689.58` 只差 **0.03%**，
说明价格正压在市场公认的价值中枢上。右侧卡片会直接给出这句「流动性判读」。

### 为什么不是 CoinGlass

最初想直接抓 `https://www.coinglass.com/zh`，实测**免密抓不到**：网页自身数据走签名接口，
`capi.coinglass.com`（官网自用域名，不是 API 域名）返回 Spring 风格 404 或空壳
`{"code":"0","msg":"success","success":true}`。

后来拿到一枚 CoinGlass API Key 实测，结论是 **Key 有效、但账号没有套餐**：

- Host 用 `open-api-v4.coinglass.com`，Header 必须是 **`CG-API-KEY`**
  （v3 时代的 `coinglassSecret` 已不认，会回到 `API key missing`）
- 带上 Key 后**所有端点**都返回 `{"code":"401","msg":"Upgrade plan"}`，
  连最基础的 `/api/futures/supported-coins`、`/api/index/fear-greed-history` 都一样
- 路径写错会返回 `404 Endpoint not found`——用这个可以区分「路径不对」和「套餐不够」

**CoinGlass 没有免费额度**（2026-09 官方价）：Hobbyist $29/月、Startup $79/月、
Standard $299/月、Professional $699/月；速率 30/80/300/1200 次每分钟。
Hobbyist 拿不到 1 小时粒度历史，要 1h 历史至少 Startup。

所以改用 **Gate.io 自身的公开真实多空/强平数据**——同样是交易所平台的真实数据，不是合成价，
只是覆盖 Gate 一家而不是全市场聚合。

> 若将来接 CoinGlass：这是纯静态站没有后端，**Key 写进 JS 等于公开**（F12 就能拿走）。
> 真要接就走后端代理，Key 放服务端。相关端点路径见 `docs.coinglass.com/reference/endpoint-overview`
> 的 Liquidation / Long-Short Ratio 两类（`liquidation/heatmap/model1|2|3`、`liquidation/map`、
> `liquidation/order` 等），别再猜路径。

## 信号窗口 与 触发提醒（2026-09-30）

用户反馈「信号一直没提示」。诊断结论是**不是因子过多**（逐个剔除任一因子，报警次数反而全部下降），
而是两件事叠加：**触发只在「刚凑齐那一根」出现一次**，而**页面只加载 200~300 根 5m**（约 25 小时）——
打开页面时触发点早就滑出窗口了。于是改了两处。

### 一、窗口拉长到 3.5 天，历史触发点画在 K 线上

| 周期 | 旧 | 新 | 覆盖 |
| --- | --- | --- | --- |
| 5m | 200 | **1000** | 16.7 小时 → **3.5 天** |
| 15m | 300 | **600** | 3.1 天 → 6.3 天 |
| 1h | 300 | 300 | 12.5 天 |

**15m / 1h 必须同步加深**，否则 5m 窗口最前面那一截映射不到已收线的粗周期，
会被判成「无表态」而白丢样本（`buildClosedMap` 返回 -1）。实测加深后映射率 **100.0%**。

数据变深了但**默认视野仍保持紧凑**（`DEF_VIEW_BARS = 260`），否则 1000 根被压成一团看不出形态；
想回看点图表头部的「**全景**」按钮即可铺满全部已加载 K 线。

实测 BTC（1000 根 5m）：窗口内触发 **8 次**，其中最近 300 根内只有 2 次 ——
**旧窗口会漏掉 6 次**。这正是「回测里 1772 次、页面上却从没见过」的直接原因。

投票面板新增**触发历史列表**（最多 12 条，含时间/方向/触发价/1h 票数/距今根数），
**点击任一行可跳到该根 K 线**；K 线上的箭头标记也改用同一批触发点（优先 `state.voteTrig`，
拿不到才回退到旧的市场结构触发点）。

### 二、新触发走四路提醒

| 通道 | 默认 | 说明 |
| --- | --- | --- |
| 页面横幅 | 开 | 顶部居中，含方向/品种/时间/触发价/三周期票数，可「看K线」跳转或关掉 |
| 声音 | 开 | Web Audio 现场合成（多=上行三音 660/880/1180，空=下行），不依赖音频文件 |
| 标题栏 | 开 | 改成「🔔 买入 BTC · SimTrader」，60 秒后复原，切到别的标签页也看得见 |
| 桌面通知 | **关** | 需用户在面板里点「开启桌面通知」显式授权，不主动索取权限 |

面板头部四个开关（横幅 / 声音 / 标题 / 桌面通知）持久化在 `localStorage`。

**两条必须守住的去重与降噪规则**：

1. **同一个触发只报一次** —— 已报过的 key（`品种|触发时间|方向`）写进 `localStorage`，
   页面每 5 分钟刷新一次也不会反复弹。
2. **只对「刚发生」的触发提醒**（`agoBars <= 3`） —— 更早的历史触发静静躺在 K 线标记
   与触发列表里，不打扰。否则每次刷新都会把窗口内的历史信号重播一遍。

浏览器自动播放策略要求先有用户交互才能出声，所以 `pointerdown` / `keydown` 上挂了解锁；
`AudioContext` 不可用时 `beepSignal` 静默返回，不抛错。

## 止盈止损的三套盈亏比口径

卡片底部同时给出三个数，三者不一致时以**扣费净口径**为准：

| 口径 | 基准 | 含义 |
| --- | --- | --- |
| 参考价口径 | 方案参考价 P | 旧口径，未扣费；会低估实际风险 |
| 预计入场价口径 | 入场区中点 | 挂单实际面对的风险收益 |
| 扣费净口径 | 入场区中点 | 再扣掉开仓 + 平仓两道手续费（市价 0.10% / 限价 0.05%） |

差额可能很大：PDF 审计的截图例子里，做空时参考价口径是 1:1.00，换成入场区中点口径是 1:1.86。

另外两处已按审计结论修正：
- **`maxAtrK` 是最终风险的硬上限**，ATR 回退分支同样受它约束（此前只筛结构止损，
  指标系数叠加后可能突破，例如 4h 的 2.4 × 1.15 × 1.08 = 2.98 > 2.8）
- 卡片右侧正负百分比**按持仓方向折算**（做空时价格下跌才是盈利，止损显示负值、止盈显示正值），
  不再是单纯的价格方向距离
- 综合价标注了**归一化权重明细**（哪几个周期、各占多少），并写明它只是加权参考值，
  不是另行识别的支撑压力位

`test-strategy.js` 的关键是**逐根 + 逐因子对照**：从 `app.js` 抽出 `computeSignal` 作为基准，
与 `strategy.js` 的流式引擎逐点比对：方向一致率 ≥ 97%、综合分数偏差 < 0.06、
**逐因子偏差 < 0.02、符号翻转 = 0**（当前 100% / 0.0000 / 0.0000 / 0）。

结构触发那条线另有三道卡：

1. **无未来函数**（测试 13）：把后 30% 的 K 线价格乘 1.37 重算，
   要求前 70% 的结构事件与分值**一字不差** —— 当前泄漏 0 / 0。
2. **窗口重放 = 全量流式**（测试 14）：看板只拿最近 200 根冷启动重放，
   回测是全程连续流式，要求方向一致率 ≥ 99.5%、分值偏差 < 0.5 —— 当前 100% / 0.00。
3. **核心条件蕴含**（测试 12）：严格档触发时三个核心条件必须齐备、宽松档必须 ≥2 个。

**200 日均线**（测试 22）单独一组，针对「长均线画到短周期图上」最容易踩的三个坑：

1. `smaCalc` 数值逐项重算一致、前 `p−1` 根为 `null`、输出长度不变；
2. `ma200FromDaily` 点数 = 根数 − 窗口 + 1；日线不足 200 根时**诚实返回空**而不是硬凑；
3. `maWindowProject` 在**宽/窄两种 K 线窗口**下都要返回 ≥2 个严格升序的点；
   且不得残留远早于 K 线的历史点（否则 `fitContent` 会把图压扁）；空输入不得抛错。

真实数据侧的验证在 `smoke-page.js` 里：用真实日线重算末点比对（偏差 < 1e-9），
并检查 5m / 15m / 1h 三种窗口的投影结果分别为 2 / 5 / 14 个点、跨度不超过 K 线。

**数据源抓取口径**（测试 23）把实测踩到的坑写死成断言：
逐笔成交不得按毫秒解释 `create_time_ms`；清算图单次请求窗口 ≤1 小时；
WebSocket 检查必须看「最后一条推送」而不只看连接状态。

它还会断言「已收线映射 0 违规」并对照证明 `buildMap` 确实包含未收线的 K 线 ——
这两条一起才能说明回测没偷看未来。

v2.1 那条线有五道卡（测试 16–21）：

1. **各层分值不越界**（16）：1H ≤ 20 / 30m ≤ 25 / 15m ≤ 30 / 5m ≤ 25、LongScore ≤ 100。
2. **Gate 蕴含**（17）：只要出了信号，六条 Gate 条件与「总分 ≥ 门槛」必须全部为真；
   且 `full ⊆ gate ⊆ choch`。
3. **无未来函数**（18）：后 30% 数据改动后，前 70% 的四层分值与 4H 背景**零泄漏**。
4. **多空对称**（19）：价格镜像（K − price，同时交换 high/low）后，
   mirror 的多头分必须等于原始的空头分。这条当场抓出过真 bug ——
   `scoreTrend` 里 EMA 幅度项写成了 `clamp01(min(slopeF, slopeS)/0.6)`，
   空头侧 slope 恒为负 ⇒ 该项恒为 0 ⇒ 空头 EMA 分永远是 3 分满分 6 的「半残」状态。
5. **规范口径回归**（21）：本次校正的四处各配一条断言 ——
   - 第 10 节：结构判成立的每一根，pivot 差值必须真的大于 `0.10 × ATR`（实测 5965 根 0 违规）
   - 第 2 节：Bull/Bear 不得在 EMA 斜率趋平时出现；三种 Regime 都要在样本内出现过
   - 第 7 节：10 个区间边界（0/49/50/69/70/79/80/89/90/100）映射到正确的区间名
   - 第 9 节：`decideNow` 必须同时返回 `confirmed` 与 `live`，且各自带独立总分与区间

这条是把「PDF 里的规范条款」直接翻译成断言。规范改了实现忘改的情况，会被这一组卡住。

## 部署注意

改了 `style.css` 或 `app.js` 后，**必须同步 bump `index.html` 里的 `?v=` 版本号**，
